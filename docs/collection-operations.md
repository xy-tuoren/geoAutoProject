# 采集运行与排查

## 继续原批次

点击“继续原批次”，选择含有 `交付图片/` 和 `调试产物/` 的批次目录。已完成题不重跑；未开始和失败题可以继续。中断时尚未开始提交的题可直接继续；可能已经搜索或发送的题显示为“待确认”，默认跳过。明确选择重新采集中断题后，会再次搜索或提问，可能产生重复记录。

```sh
npm run run:android -- --serial <设备> --resume-batch <批次目录>
# 只有确认允许重新采集中断题时才加 --retry-uncertain
```

每题执行前先将 `pending` 改为 `running` 并保存；提交问题前先落盘 `submission_started=true`；完成、失败或停止后更新结果。断电或进程异常退出留下的 `running`，只有明确记录尚未提交时才恢复为 `pending`，否则转为 `needs_confirmation`。汇总通过同目录临时文件加重命名原子替换，避免半截 JSON。新旧批次都可读取；旧版缺失的未开始题不能凭空恢复。

## 产物版本 9

交付目录结构不变，仍只保存最终正式 PNG。问题调试目录下每次建立新的 `尝试_001/` 等目录，保存本次 `回答.json`、`回答.xml`、`性能分析.json`、`执行日志.jsonl`、接缝和失败现场。未完成的图片只在本次尝试的 `待交付/` 内；成功后整题 PNG 移至交付区，元数据指向最终绝对路径。历史诊断不移动、不覆盖；旧版失败题留下的交付残片保存到新尝试的 `旧交付现场/`。

`batch-summary.json` 记录完整计划与每题最新状态、尝试目录和结果；事件使用 `event_id`、`stream_id`、`run_id`、`attempt_id` 区分重启和重试，单个流内的 `sequence` 单调增加。每次启动或继续批次独立保存 `环境_<run_id>.json`，包含采集工具版本、电脑运行时、手机系统和所选应用版本。读取失败的环境字段明确标记，不影响其他证据。

结果字段：

| 字段 | 含义 |
| --- | --- |
| `status` | pending / running / completed / failed / needs_confirmation |
| `content_type` | answer / search_results_only / app_limited |
| `quality_status` | verified / needs_review（接缝采用保留整屏降级） |
| `result_label` | 面向操作人员的中文结果 |
| `human_reviewed` | 默认 false，不能将自动校验当作人工验收 |

应用限制提示的成功只表示已保存应用实际展示页面，不代表取得隐藏内容。图片加载、药品首末项、引用展开和接缝校验继续执行。

## 排查顺序

1. 从汇总定位题目与具体尝试目录。
2. 查看错误码、中文原因和处理建议，再看失败现场的原始错误及 `cause`。底层 `code`、`details`、`method` 一并保留。
3. 对照环境版本、阶段时间线与各份证据的采集时间。失败截图和之后取得的 XML 不保证同一时刻，不能直接混用坐标。
4. 搜索、引用和本题定位问题优先查看 `关键识别/`：包含当时 OCR 使用的图像、SHA-256、候选、定位规则、目标或拒绝说明，以及附近 XML 的独立时间。同一用途保留最后一次观察，点击前先落盘；引用确认另留确认用途的证据。

```sh
node scripts/replay-recognition.js <关键识别/证据.json>
```

该命令完全离线，用已保存的 OCR 候选重新执行当前定位函数；不会连接手机、点击、输入或重新提交问题。原图存在时先验证校验值。支持抖音/头条首屏入口、引用资料和问题定位；不支持的用途明确报错。它用于验证定位规则，不能替代真机截图完整性验收。

## 停止和性能

点击停止后界面立即反馈；后台先拒绝新操作、取消等待和 ADB 子进程、停止 sidecar 进程树，再保存进度和恢复常亮。已送达手机的操作不能撤销，中断题不得自动重放。用户停止不再重新向手机取失败现场，保存已有阶段与操作证据。恢复常亮失败时日志明确提示。

控制台将相同等待和 OCR 未命中提示按 5 秒合并，原始事件仍完整落盘。性能报告保留按操作聚合和阶段时间线。OCR 仅缓存最近一张字节完全相同、选项相同的图片，命中会记录 `ocr_exact_frame_reused`；画面或参数变化重新识别。只读取尺寸时可复用同一时刻正在传输的 PNG，正式稳定性校验不会合并两次独立截图。
